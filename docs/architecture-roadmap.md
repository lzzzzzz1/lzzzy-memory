# 全球情侣旅行记忆 · 参考项目拆解与稳定版路线

## 产品北极星

打开产品后立即看到一颗可拖动、可缩放的真实地球。去过的城市以克制的光点被点亮；点击城市直接进入该城市的私密档案，查看历次到访的文字、照片和视频，并能继续添加新的回忆。地图是主界面，时间轴与旅行列表是辅助入口。

## 两个参考项目的取舍

### Map of Us

值得采用：

- 地图、城市、回忆档案之间的完整闭环。
- 回忆按城市和时间双重组织。
- 城市点亮进度、空状态和明确的“回到地图”路径。
- 编辑、删除、完整备份导出与导入恢复。
- 本地优先、数据目录可迁移、安装后数据与应用资源分离的可靠性思路。

不直接采用：

- D3 + 中国 GeoJSON 适合中国省市下钻，不适合全球可旋转 3D 地球。
- 单机密码和本地 JSON 不满足两部手机实时共享。
- 省份层级不符合当前“国家 + 城市，最低到城市”的产品边界。

### ToWhereOnline

值得采用：

- Cesium 地球作为主场景，城市点位可点击并进入独立城市详情。
- 卫星图与街道图的分层思路、相机飞行动画、城市标签避让。
- 保持地球组件挂载，进入城市详情时避免重新初始化重型 WebGL 场景。
- 星空氛围和点亮城市的情绪表达。

不直接采用：

- 单个 Cesium 组件混入月球、滚动叙事、城市巡游、照片弹层和多套动画，维护成本高。
- 多个永久 `requestAnimationFrame`、逐帧标签 O(n²) 避让和过大的瓦片缓存对手机不友好。
- 匿名可读写 RLS、公共媒体桶和 GitHub Token 客户端状态不适合私密情侣数据。
- React Three Fiber 与 Cesium 两套地球并存会增加包体、显存和故障面。

## 当前项目审计

### 已有优势

- Next.js 16、React 19、TypeScript strict、Supabase Auth/RLS 与私有 Storage。
- Cesium 已完成动态加载、静态资源本地化和移动端相机灵敏度控制。
- 数据以 `couple_id` 隔离，媒体只保存对象键并通过签名链接读取。
- 已支持国家/城市输入、文字、照片、视频和登录状态恢复。

### 高风险问题

1. `Atlas` 同时负责导航、地图、表单、保存、时间轴和通知，继续扩展会快速失控。
2. 地点、旅行地点、回忆和媒体分多次客户端写入，数据库层缺少一个原子事务。
3. `trip_places.position` 由客户端协调，并发设备仍可能产生竞争。
4. 当前模型把“地点”和“一次到访”混在一起，无法自然表达同一城市多次旅行。
5. 媒体表支持多条记录，但加载层只取每段回忆的第一条，表单也只允许一个文件。
6. 缺少编辑、删除、备份恢复、上传大小限制、图片压缩和失败重试队列。
7. 城市目录有限，外部地理编码不可用时会阻塞不在目录内的城市。

## 目标信息架构

- 地球：主入口，显示所有点亮城市。
- 城市档案：城市概览、历次到访、全部照片/视频/文字，支持继续记录。
- 旅行：一次出行，可包含多个城市。
- 时间轴：跨城市按日期浏览所有回忆。
- 设置与数据：成员、隐私、备份导出、导入恢复、设备测试。

## 目标数据模型

- `places`：情侣空间内规范化城市，保存国家、城市和城市级坐标。
- `trips`：一次旅行的名称与日期范围。
- `visits`：某次旅行对某座城市的一次到访；同一城市可以有多次到访。
- `memories`：归属一次 `visit`，保存标题、文字、日期和乐观并发版本。
- `media`：一段回忆可有多张照片或多个视频，保存排序、MIME、尺寸与对象键。

核心写入应由数据库 RPC 在事务中完成：确定或创建城市 → 创建到访 → 创建回忆 → 创建媒体元数据。文件先上传到私有临时对象键；事务失败则删除对象，事务成功后才在界面展示。

## 分阶段实施

### P0：稳定闭环

- 城市与回忆正确关联。
- 点击地球标记打开城市档案。
- 新增地点/回忆写入无重复排序、空文件误判或半保存。
- 清晰错误提示与可重试状态。

### P1：正式数据模型

- 增加 `visits`，支持同城多次到访。
- 使用事务 RPC 代替多次客户端写入。
- 一段回忆支持多媒体、排序、压缩与大小限制。
- 编辑、删除、版本冲突和双设备刷新。

### P2：长期使用能力

- 完整备份导出、校验、导入预览与恢复。
- 城市搜索目录扩充，离线目录优先、服务端地理编码兜底。
- 地图图层切换、相机飞向城市、标签避让与按距离显示。
- PWA 离线壳、失败上传队列、设备性能日志。

### P3：体验精修

- 城市封面、照片墙、年度回顾和旅行故事。
- 地球点亮进度、国家统计和双方贡献标记。
- Craft 式渐进操作、键盘快捷键和移动端底部 Sheet。

## 已确认的产品决策

1. 同一城市允许记录多次到访，以 `visits` 作为正式模型。
2. 一段回忆默认最多 20 张照片和 2 个视频；上限保存在 `couple_settings`，以后可以提高。
3. 加入包含数据库记录和私有媒体本体的本地备份、完整性校验、导入预览与安全恢复。
4. 城市详情采用“快速抽屉 + 完整城市档案页”两级结构。
